### 二、实现要点

**服务层（对外只读目录，视图只做编排）**

- `services/training.py`：`TrainingRecord` 只声明 8 个对外字段（`code` / `train_size` / `test_size` / `train_mse` / `train_r2` / `test_mse` / `test_r2` / `model_type`），`TrainingCatalog` 从 `config.json` 的 `training` 段取数；站点清单里没有的编码跳过并记日志，样本数非整数、缺字段、负值等配置错误转成可读的 `DATA_UNAVAILABLE`。
- `services/announcements.py`：`Announcement` + `AnnouncementCatalog`，按发布时间倒序；支持 `active: false` 下架；单条格式不对只跳过并记日志，整份读不到才返回可读错误，页面不会崩。`published_at` 接受 `2026-11-20` 或带时区的 ISO 时间。
- `services/sources.py`：改为来源注明目录，`DataSource` 只含 `key` / `name` / `category` / `purpose` / `update`，**不再推导路径**，也不再读 `settings`。五类来源集中在 `ATTRIBUTIONS`。
- `services/catalog.py`：改为 `SiteCatalog` 装配器，把训练情况/来源/公告三个目录按需构建，视图与测试从同一入口取数（对外内容单一数据源）。
- `services/features.py`：保留为**内部**特征登记表（特征 → 气象变量 / 换算），`weather.py` 从它派生 `FEATURE_VARIABLES` / `FEATURE_TRANSFORMS`，删除两处重复定义；该文件不参与任何对外展示。
- `services/rf.py`：删除已无对外用途的模型文件状态查询（`ModelStatus` / `status()`）；缺模型或加载失败只返回"该站点的模型暂不可用"，路径与文件名只进日志。
- `services/config.py`：`DataPaths` 增加公告配置路径，`Configuration` 增加 `training` 段；对外错误文案去掉文件名。
- `services/errors.py`、`geo.py`、`matching.py`、`weather.py`：所有会展示给访客的错误文案改为面向访客的表述（不提文件、字段名、变量名、模块名），原始异常继续放在 `detail` 里进日志。

**视图与路由**

- `GET /stations/` → 训练情况页（`training_page`，模板 `training.html`）；`GET /sources/` → 来源页。两页地址与 v1.1.1 相同，站内链接与外部书签不受影响。
- 只读接口：`GET /api/stations/`（训练情况）、`GET /api/sources/`（来源注明）、`GET /api/announcements/`（公告，新增）；三者统一走 `_readonly_response()`，成功附 `ok` / `meta`，业务错误按 `STATUS_BY_CODE` 转状态码。三个接口都是 `@require_GET`，写请求返回 405。
- `home` 与 `predict_api`、旧纯文本分支的代码路径与返回结构保持不变。

**前端**

- `base.html` 抽出 `{% block body %}`，首页用它换成三栏布局，其余页保持单栏；模板内的维护注释改用 `{# … #}`，不再以 HTML 注释形式出现在页面源码里。
- `common.js`：新增 `sourceNames()`（来源 key → 名称），结果区署名与来源页共用 `/api/sources/` 的同一次请求。
- `app.js`：结果区"气象来源""分区依据"改为署名式标注，文案全部取自来源接口（如"来源：中国土壤分区、中国气候分区"），不再显示气象模型名或图层文件名。
- `training.js`：渲染 8 列指标表，精度取接口返回的 `display`（`mse_digits` / `r2_digits`），样本数取整并按千分位；检索走站点编码，R² 区间按测试集筛选，重置恢复全部。
- `notices.js`：公告按后端顺序渲染，正文按空行分段。
- `style.css`：新增三栏布局、左侧导航框、公告卡片与指标表样式，沿用原有变量；`≤900px` 时左三框与公告边栏堆叠到主内容上下，`≤560px` 表单与来源卡片单列，表格在容器内横向滚动，页面本身不出现横向溢出。

**配置**

- `config.json` 新增 `training` 段：`model_type`、`display`（展示精度）、`records`（12 个站点的训练结果）。
- 新增 `announcements.json`：公告条目（标题 / 正文 / 发布时间 / 可选 `active`）。

### 三、接口契约

`GET /api/stations/`（200）——只含训练情况字段：

```json
{
  "ok": true,
  "count": 12,
  "display": {"mse_digits": 4, "r2_digits": 4},
  "stations": [
    {
      "code": "NMG",
      "train_size": 2045, "test_size": 512,
      "train_mse": 1.1417, "train_r2": 0.9947,
      "test_mse": 17.856, "test_r2": 0.9263,
      "model_type": "随机森林 / RandomForestRegressor"
    }
  ],
  "meta": {"generated_at": "2026-11-20T14:00:00+00:00", "took_ms": 3}
}
```

`GET /api/sources/`（200）——只含来源署名：

```json
{
  "ok": true,
  "count": 5,
  "sources": [
    {"key": "weather", "name": "Open-Meteo 实时气象数据", "category": "气象数据",
     "purpose": "提供预测时所需的当日实时气象要素取值，作为模型输入的外部数据来源。",
     "update": "由公开气象数据服务持续更新，本站实时获取，无需人工维护。"}
  ],
  "meta": {"generated_at": "2026-11-20T14:00:00+00:00", "took_ms": 1}
}
```

`GET /api/announcements/`（200，新增）——只读，按发布时间倒序：

```json
{
  "ok": true,
  "count": 3,
  "announcements": [
    {"title": "站点模型训练情况已公开", "body": "……", "published_at": "2026-11-20"}
  ],
  "meta": {"generated_at": "2026-11-20T14:00:00+00:00", "took_ms": 1}
}
```

失败沿用既有风格：HTTP 500 + `{"ok": false, "error": {"code": "DATA_UNAVAILABLE", "message": "…"}}`；写请求 405。
