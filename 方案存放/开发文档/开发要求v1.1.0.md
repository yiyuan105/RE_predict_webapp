# 需求文档：RE_predict_webapp 站点匹配与预测升级

## 1. 项目概述

本项目为基于 Django 框架的 Web 应用，已实现最小可行性产品（MVP）。当前工作区根目录结构包含 `models` 文件夹、`mysite` 文件夹、`RE_predict_webapp` 文件夹与 `manage.py` 文件，为典型 Django 项目结构。

本次需求为在**不改动原有框架**的前提下，升级后端的站点匹配与随机森林预测逻辑，并同步更新前端展示。遵循**模型与逻辑分离**原则。

## 2. 约束条件

- 保持原有 Django 框架不改变。

## 4. 功能需求

### 4.1 输入

用户在前端页面输入**经度、纬度**。

### 4.2 中国陆地范围判断

- 依据根目录 `models` 中的**中国地理边界 geojson**，判断输入经纬度是否落在中国陆地内。
- 若不在陆地范围内，返回相应提示，不进行后续预测。

### 4.3 站点匹配逻辑（多级降级匹配）

在经纬度位于中国陆地内的前提下，将经纬度依据**中国气候分区 shp** 与**中国土壤分区 shp** 匹配站点，按以下优先级依次尝试：

1. **第一优先级：同类土壤 + 同类气候**
   - 同时满足同类土壤与同类气候的站点中，按**最近原则**匹配。
2. **第二优先级：同类气候（去掉土壤筛选）**
   - 若第一优先级无匹配站点，去掉土壤限制，在同类气候站点中按最近原则匹配。
3. **第三优先级：去掉土壤限制，再次最近站点匹配**
   - 若仍无匹配，按空间最近站点进行匹配。
4. **第四优先级：直接按空间最近站点匹配**
   - 若仍无匹配站点，直接以空间最近站点作为匹配结果。

> 说明：若 shp 使用方式不明确，参考已放入对应文件夹内的示例实现。

### 4.4 随机森林预测

- 根据最终匹配到的站点，直接调用随机森林模型进行预测。
- 将预测值返回前端页面展示。

### 4.5 置信度输出

根据匹配级别输出置信度：

| 匹配情况 | 置信度 |
|----------|--------|
| 土壤 + 气候最优匹配 | 高 |
| 仅气候匹配 | 中 |
| 均未匹配、按最近站点匹配 | 低 |

### 4.6 前端调整

- 可对前端进行相应更改，用于展示预测值与置信度。
- 保持原有页面框架，仅做必要改动。

## 5. 架构要求

- **模型与逻辑分离**：随机森林模型加载、geojson/shp 解析、站点匹配、预测调用等应拆分为独立模块，与 Django 视图层解耦。
- 遵循面向对象设计，各职责封装为类。
- 便于后续替换模型、更新边界数据或调整匹配策略。

## 8. 验收标准

1. 输入不在中国陆地的经纬度时，返回范围提示且不预测。
2. 输入中国陆地内经纬度时，按四级降级匹配逻辑正确匹配站点。
3. 预测值与置信度正确返回并在前端展示。
4. 原有 Django 框架未改动，工作区外文件未改动。
5. 根目录存在更新日志与维修手册 md 文件。
6. shp 读取与匹配逻辑参考示例实现并正确工作。
7. 模型与逻辑分离，核心逻辑与 Django 视图解耦。
