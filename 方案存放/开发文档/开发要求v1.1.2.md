# 需求文档：RE_predict_webapp 前端对外化改版（v1.1.2）

## 1. 项目概述

本项目为基于 Django 框架的 Web 应用（生态系统呼吸 Re 在线预测站点），已完成 v1.1.0（中国陆地范围判断 + 气候/土壤四级降级匹配 + 随机森林预测 + 置信度）与 v1.1.1（多页面前端、网页简述、站点模型查看、数据来源栏目）。

本次需求（v1.1.2）为对**前端进行"对外化"改版**：在**保留现有视觉风格、配色与导航结构**的前提下，把页面从"对内可读"调整为"对外展示"，**隐去系统内部结构**。具体地：

- 页面**不出现任何文件地址 / 路径 / 文件名**；
- **不展示内部实现细节**，包括模型文件、模型输入特征、内部变量与接口契约等；
- 原"站点模型查看"功能改为只展示**模型训练情况**（每个站点的训练/测试样本规模、训练集与测试集的均方误差 MSE 与决定系数 R²、模型类别），不含模型文件或输入特征；
- 原"数据来源栏目"改为只做**来源注明（署名式说明）**，仅注明来源名称、类型、用途与更新说明，不给出路径，不展开模型文件 / 输入特征 / 变量；
- **新增公告功能**：服务端可发布公告（标题与正文内容均由发布方自行拟定），公告在**首页右侧边栏**集中展示；
- **调整首页整体布局**：把"首页 / 站点 / 数据来源"三项作为**左侧从上到下依次排列的三个框**布置，公告占据首页右侧边栏。

在产物交付与运维侧，本次还明确以下要求：

- **更新日志与维修手册在其原位置就地更新**，不新建副本、不改名、不移动路径；
- 将**部署相关内容从维修手册中抽出**，单独成一份**《云端部署与更新》文档**，存放在**与本开发要求（方案）相同的文件夹**中；部署**完全使用 Docker**，维修手册仅保留部署以外的运维内容并指向该独立文档；
- **开发完成后自动上传 Git**：本次改动（代码与文档产物）须自动提交并推送到项目 Git 仓库。

后端在不改动原有框架与匹配 / 预测逻辑的前提下，仅按需精简对外接口返回内容（去除内部字段），并新增供公告展示的只读数据通道，**不得改变 v1.1.0 已实现的预测结果与对外行为**。

## 2. 约束条件

- 仅改动当前工作区内文件，**不得改动工作区外文件**。
- 保持原有 Django 框架与目录结构不变，遵循**模型与逻辑分离**原则。
- **保留现有前端风格**：沿用既有配色、字体、置信度徽标等视觉语言，新内容在此基础上扩展，不得推倒重做整体观感。
- **不破坏 v1.1.0 / v1.1.1 既有功能**：首页预测流程、预测主链路与对外接口的可用行为保持兼容。
- **对外化原则（本版核心，仅约束对外可见层）**：所有对外可见的**前端页面与对外接口返回内容**，一律**不暴露内部结构**——不写文件地址 / 路径 / 文件名，不展示模型文件、输入特征、内部变量、内部模块划分或接口实现细节。**该原则不适用于内部文档与代码仓库**：运维文档、部署文档、Git 仓库内部按需要可包含路径、镜像、命令等实现细节，只要这些内容不通过前端页面或对外接口暴露给访客即可。
- 对外展示的"模型信息"以**训练情况指标**为限；对外展示的"数据来源"以**来源署名**为限。
- 公告由服务端发布与维护，**面向访客的公告展示接口一律为只读**；公告本身不得包含文件地址、内部实现或与对外展示无关的技术信息。
- 后端除公告维护外的新增 / 调整接口一律为**只读**，不涉及预测相关业务的数据写入，不改变匹配策略与预测编排逻辑。
- **文档就地更新约束**：更新日志与维修手册必须在其**原有路径**上就地追加 / 修订（更新日志追加 v1.1.2 条目；维修手册删去部署章节并指向独立部署文档），不得另存为新文件、不得改名或移位。
- **部署文档独立约束**：云端部署与更新相关内容**只集中出现在《云端部署与更新》文档**中，维修手册不再重复承载部署步骤；两文档之间以引用衔接，避免多处硬编码不一致。
- **部署方式约束**：部署**完全使用 Docker**，以容器化方式交付与更新，文档需给出可复现的 Docker 部署与更新流程。
- **Git 自动上传约束**：开发（含代码与文档产物）完成后须自动执行 `git add` / `git commit` / `git push` 推送到项目既有远程仓库；提交应信息清晰、可追溯，不提交敏感凭据（如真实密钥、密码），仓库内部的 .gitignore 等约定保持不变。
- 代码干净整洁、尽量封装，遵循面向对象原则；注释只写"为什么"和不直观的约定。
- 展示内容尽量数据驱动、集中配置，便于后续增删站点、来源与公告时无需大改文案。

## 4. 功能需求

### 4.1 前端整体改版（对外化，保留风格与导航）

- 延续 v1.1.1 的多页面结构与统一导航，改版目标是**对外展示口径的收敛**与首页布局重组，而非新增预测功能。
- 改版后首页**保留原有输入经纬度 → 展示预测值 / 置信度 / 匹配方式 / 站点 / 距离 / 坐标的完整交互**，行为不退化。
- 视觉风格延续既有样式体系，新增 / 调整的内容块（训练情况卡片、来源说明块、公告边栏、左侧三个导航框）使用同一套配色与组件语言，避免风格割裂。
- **页面全文不出现任何文件地址、路径、文件名或内部模块名**；涉及"来源""数据""模型""公告"的表述一律以对外可读的自然语言呈现。

### 4.2 首页布局重组（左侧三框 + 右侧公告边栏）

- 首页采用**左栏 + 主内容 + 右侧边栏**的整体布局：
  - **左侧栏**：自上而下依次布置**三个框**——"首页""站点""数据来源"，作为站点级导航入口（点击"首页"回到预测主页面，点击"站点"进入站点 / 模型训练情况页，点击"数据来源"进入来源注明页）；三个框风格统一、垂直堆叠，宽度固定。
  - **右侧边栏**：展示**公告**（见 4.5），首页固定可见。
  - **主内容区**：保留原有经纬度输入与预测结果展示。
- 左侧三个框与右侧公告边栏均使用既有配色与组件语言，窄屏 / 移动端时按响应式规则堆叠（不出现横向溢出）。

### 4.3 网页简述（对外化口径）

- 每个页面标题下保留一段"网页简述"，用 1–3 句中文说明该页面"是做什么的、给谁用、如何使用"，文案集中管理。
- 简述内容遵循对外化原则：只描述页面用途与使用方式，**不提内部实现、不提文件与变量**。

### 4.4 模型训练情况查看功能（替代原"站点模型查看"）

- 将原"站点模型查看页"调整为**模型训练情况查看**，以列表或卡片形式按站点展示其训练结果概况。每个站点至少包含且**仅包含**下列对外可见字段：
  - 站点编码；
  - 训练样本数（Train size）、测试样本数（Test size）；
  - **训练集均方误差（MSE）与训练集决定系数（R²）**；
  - **测试集均方误差（MSE）与测试集决定系数（R²）**；
  - 模型类别（统一为"随机森林 / RandomForestRegressor"）。
- **每个站点的训练集与测试集的 R² 和 MSE 四项指标均需完整展示**，不得只展示其中某一项或仅展示单一数据集的指标。
- **不得展示**：模型文件、模型输入特征清单、内部变量、任何路径或文件名。
- 展示精度遵循统一约定（建议：MSE 保留 4 位小数、R² 保留 3 位小数；样本数取整），由集中配置驱动，便于后续统一调整。
- 提供轻量检索 / 筛选（如按站点、按测试集 R² 区间筛选），实现从简，可基于前端已加载的站点训练数据完成。

### 4.5 公告功能（服务端发布，首页右侧边栏展示）

- 提供**公告功能**：发布方可在**服务端**发布公告，每条公告包含**标题**与**正文内容**（标题、正文均由发布方自行拟定），并可附发布时间。
- 公告**集中数据驱动管理**（标题 / 正文 / 发布时间为结构化的公告条目），便于后续新增、编辑与下架，新增公告无需改动前端结构。
- 公告在**首页右侧边栏**展示，多条公告按**发布时间倒序**排列（最新在上）；右侧边栏可滚动或以紧凑卡片呈现，避免遮挡主内容。
- 公告展示遵循对外化原则：公告正文为面向访客的自然语言，**不得出现文件地址 / 路径 / 文件名 / 内部实现细节**。
- 后端提供**只读**的公告数据通道供首页右侧边栏渲染（返回标题、正文、发布时间），不开放面向访客的公告写入接口；发布 / 维护公告为服务端运维操作。

### 4.6 数据来源栏目（改为来源注明）

- 将原"数据来源栏目"调整为**对外来源注明**：只说明系统所依赖的来源"是什么、用来做什么、由谁/何途径提供、如何更新"，**不给出任何路径、文件名、地址或内部字段**。
- 每条来源仅给出：来源名称、来源类型、用途、更新方式（自然语言描述）。建议覆盖以下来源类别（以对外可读措辞表述，不含路径与变量）：
  - **预测模型来源**：各观测站点基于历史观测数据训练的随机森林模型；说明按站点分别训练，用于 Re 预测。
  - **地理边界来源**：中国陆地（省级）边界数据，用于判断输入经纬度是否落在中国陆地范围内。
  - **气候分区来源**：中国气候分区数据，用于气候"同类"判定与站点匹配。
  - **土壤分区来源**：中国土壤分区数据，用于土壤"同类"判定与站点匹配。
  - **实时气象特征来源**：公开气象数据服务提供的实时气象要素取值，作为模型输入的外部来源（只注明来源，不罗列具体变量名与接口细节）。
- 来源注明内容数据驱动、集中配置，便于后续增删来源时无需大改文案；可在预测结果处以简短方式对关键来源做署名式标注，标注内容与来源页同源。

### 4.7 后端支撑（对外接口精简 + 公告只读通道）

- 在不改动预测主链路的前提下，将供新页面调用的只读接口的**返回内容收敛为对外可见字段**：
  - 模型查看相关：仅返回各站点的训练情况指标（训练/测试样本数、训练/测试 MSE 与 R²、模型类别），**移除模型文件路径、输入特征清单、内部变量等字段**；
  - 来源相关：仅返回来源名称、类型、用途、更新说明，**移除任何路径 / 地址 / 文件名 / 内部字段**；
  - 公告相关：**新增只读接口**返回公告列表（标题、正文、发布时间，按发布时间倒序），供首页右侧边栏渲染；公告的发布 / 维护通过服务端运维完成，不开放对外写入接口。
- 接口的路由与对外行为保持向后兼容；错误处理沿用既有状态码风格，数据缺失以可读提示返回，不得使页面崩溃。

### 4.8 页面框架与兼容

- 沿用既有模板组织方式与公共导航 / 页脚 / 样式片段，新内容（左侧三框、右侧公告边栏、训练情况渲染、来源注明渲染）置于对应页面 / 公共组件，避免每页复制。
- 既有纯文本接口与预测主接口对外行为保持不变，保证向后兼容。

### 4.9 文档与交付（就地更新 + 部署独立 + Git 自动上传）

- **更新日志（原位置就地更新）**：在原有"更新日志"文件上追加 v1.1.2 条目（不新建副本、不改名、不移动路径），记录本版前端对外化改版、模型查看改为训练情况展示（每站点训练/测试 MSE 与 R² 全展示）、数据来源改为来源注明、新增公告功能与首页"左三框 + 右公告边栏"布局、对外接口字段精简与公告只读通道、文档就地更新与部署抽离、以及自动上传 Git 等变更，并说明对 v1.1.0 / v1.1.1 的兼容情况。
- **维修手册（原位置就地更新）**：在原有"维修手册"文件上就地修订，**将其中的部署相关内容移出**（不再保留部署步骤），改为指向独立的《云端部署与更新》文档；保留并补充部署以外的运维内容——训练情况展示与来源注明的内容维护方式、公告的发布与维护流程（服务端操作，含标题 / 正文 / 时间）、对外接口字段范围、如何新增站点训练结果与来源条目等。
- **《云端部署与更新》文档（新增）**：与**开发要求（本方案）相同的文件夹**下新建一份独立的部署文档，**集中、完整地承载云端部署与更新方案，完全使用 Docker**：镜像构建、容器编排（如 docker-compose）、端口映射、环境变量与配置注入、数据/模型卷挂载、首次部署流程、更新与回滚流程、健康检查与故障排查；可包含内部路径、镜像名与命令等实现细节（属内部文档，不通过前端对外暴露）。维修手册中不再重复部署步骤，仅做交叉引用，确保部署内容单一来源。
- **开发完成后自动上传 Git**：代码改动与上述文档产物完成后，自动执行 `git add` → `git commit`（提交信息清晰概括本版变更）→ `git push` 推送到项目既有远程仓库；不提交敏感凭据，沿用既有 .gitignore。

## 5. 架构要求

- **模型与逻辑分离延续既有版本**：页面数据获取仍通过服务层与集中配置完成，视图层只做编排与响应；本版只是把"对外可见层"的内容范围收窄并重组首页布局。
- 前端按"多页面 + 公共组件"组织：导航、左侧三框、网页简述片段、训练情况渲染、来源注明渲染、公告边栏渲染尽量复用。
- 训练情况、来源注明与公告**单一数据源**：页面展示、相关只读接口、结果区标注同源，避免多处硬编码不一致。
- **部署单一来源**：Docker 部署与更新步骤只集中在《云端部署与更新》文档，维修手册仅引用、不重复，避免两处不一致。
- 便于后续替换与增删：新增站点训练结果、新增来源、新增 / 下架公告仅需修改集中配置或运维发布即可出现在对应页面，无需改前端结构。

## 6. 输出产物

开发完成后，按"就地更新 / 同文件夹新增"两类落点输出 / 更新：

1. **更新日志**（md 格式，**在原位置就地追加 v1.1.2 条目**，不新建副本、不改名、不移动路径；内容见 4.9）。
2. **维修手册**（md 格式，**在原位置就地修订**：移除部署章节并指向独立部署文档，保留并补充训练情况与来源维护、公告发布维护流程、对外接口字段范围、新增站点 / 来源条目方法等部署以外的运维内容；运维侧涉及内部路径仅在文档内说明，不在对外页面展示）。
3. **《云端部署与更新》文档**（md 格式，**新增，存放到与本开发要求（方案）相同的文件夹**）：完全使用 Docker 的云端部署与更新方案，覆盖镜像构建、容器编排、端口/环境配置、数据/模型卷挂载、首次部署、更新与回滚、健康检查与故障排查；为内部文档，可含实现细节，维修手册对此仅作引用。
4. **README**（md 格式，更新页面列表、首页布局说明（左侧首页/站点/数据来源三框 + 右侧公告边栏）与对外能力说明，去除对外可见的内部路径表述，并把部署相关指引改为指向《云端部署与更新》文档）。
5. **Git 提交**：以上代码与文档改动完成后，自动 `git add` / `git commit` / `git push` 到项目既有远程仓库。

## 7. 非功能性需求

- 保留现有视觉风格，改版前后观感一致、协调。
- 改版以可读、可维护为先，不引入不必要的大型前端框架；脚本沿用既有前端脚本风格。
- 训练情况、来源注明与首页公告边栏在窄屏 / 移动端基本可用，左侧三框与右侧公告边栏按响应式规则堆叠，表格与卡片不出现横向溢出。
- **对外信息最小化（仅对外可见层）**：任何前端页面、对外接口返回、文案、公告正文中均不得出现文件地址、模型文件、输入特征与内部变量；内部文档（维修手册、部署文档）与代码仓库不受此限，但相关内容不得经由前端页面或对外接口暴露。
- 不破坏现有预测功能与对外接口契约。
- **可复现的部署**：Docker 部署文档应可在新环境按文复现部署与更新，步骤明确、命令可执行，与项目实际容器配置一致。
- **文档一致性**：更新日志 / 维修手册在原位置更新、部署内容单一来源（仅部署文档），避免多文档重复或冲突。

## 8. 验收标准

1. 前端在**保留既有配色与组件风格、保留多页面与导航**的前提下完成对外化改版，无功能退化。
2. **所有对外前端页面全文不出现任何文件地址 / 路径 / 文件名 / 内部模块名 / 接口实现细节**。
3. 首页布局符合"左三框 + 右公告边栏"：**左侧自上而下依次为"首页""站点""数据来源"三个框**，导航入口可用；**首页右侧边栏展示公告**，公告按发布时间倒序排列；主内容区预测交互不退化。
4. 模型查看页面（训练情况查看）按站点正确展示：站点编码、训练 / 测试样本数、**训练集与测试集的 MSE 与 R² 四项指标均完整展示**、模型类别（随机森林），与给定训练结果数据一致；**不展示模型文件、输入特征、变量**。
5. 训练情况展示精度遵循统一约定，由集中配置驱动；筛选 / 检索可正常使用。
6. 公告功能可用：服务端可发布公告（自定义标题与正文 + 发布时间），公告在首页右侧边栏正确渲染并支持多条倒序展示；公告正文不含路径 / 内部实现；公告的对外展示走只读接口，无面向访客的写入接口。
7. 数据来源页面（来源注明）仅以自然语言注明来源名称、类型、用途与更新方式，覆盖预测模型 / 地理边界 / 气候分区 / 土壤分区 / 实时气象特征等来源类别，**不含路径、文件名、地址与内部变量**。
8. 结果区如有来源标注，与来源页同源一致，且不引入路径等内部信息。
9. 供页面调用的只读接口返回内容已收敛为对外可见字段，移除内部路径 / 模型文件 / 输入特征 / 变量；新增公告只读接口按倒序返回标题 / 正文 / 时间；接口向后兼容，数据缺失时返回可读错误而非页面崩溃。
10. 既有纯文本接口与预测主接口对外行为与返回结构保持向后兼容；原有 Django 框架与目录结构未改动，所有改动均在工作区内，视图层未重复实现取数逻辑。
11. **更新日志与维修手册均在其原位置就地更新**：未新建副本、未改名、未移动路径；更新日志含 v1.1.2 条目；维修手册已移除部署章节并指向《云端部署与更新》文档，且仍完整承载公告 / 训练情况 / 来源等运维内容。
12. **《云端部署与更新》文档已新增并存放于本开发要求（方案）所在文件夹**，内容完全使用 Docker，覆盖镜像、编排、端口/环境配置、数据/模型卷、首次部署、更新与回滚、健康检查与故障排查，可作为可复现部署依据；维修手册不重复部署步骤，二者以引用衔接。
13. **开发完成后改动（代码 + 文档）已自动 `git add` / `git commit` / `git push` 到既有远程仓库**：提交信息清晰可追溯，未提交敏感凭据，沿用既有 .gitignore。
14. 框架自检与既有测试全部通过，并对外接口字段精简、训练情况全指标展示、公告功能与首页布局、文档就地更新与部署抽离、自动 Git 上传补充必要测试 / 校验。
