## 3. 数据更新

### 3.1 增删或修改站点

编辑 `RE_predict_webapp/config.json` 的 `stations`：

```json
"NEW": {
  "site_name": "新站点名称",
  "ecosystem": "Forest",
  "veg_type": "...",
  "lat": 30.0,
  "lon": 110.0,
  "soil_type": "红壤",
  "climate_type": "北亚热带湿润地区"
}
```

- 站点分区类型优先由 shp 自动查询；`soil_type` / `climate_type` 只在 shp 未覆盖该点时兜底，写错了不会报错但会参与匹配，建议照 shp 结果填写。
- 新增站点必须同时放入模型 `models/rf_models/NEW_rf.joblib`，否则命中时会返回 `MODEL_UNAVAILABLE`。
- 不需要改任何代码；重启服务生效（单例缓存在进程内）。

### 3.2 替换随机森林模型

把同名的 `<站点>_rf.joblib` 覆盖到 `models/rf_models/`，重启服务。模型输入是 `config.json` 里 `features` 顺序的 6 个特征：

| 特征 | 含义 | 来源 |
|------|------|------|
| `rn` | 净辐射 = 短波辐射 × 0.6 | `shortwave_radiation` |
| `ts1` | 气温 | `temperature_2m` |
| `rh` | 相对湿度 | `relative_humidity_2m` |
| `pa` | 气压 | `surface_pressure` |
| `soil_moisture_0_to_7cm` | 0–7cm 土壤水分 | 同名变量 |
| `soil_moisture_7_to_28cm` | 7–28cm 土壤水分 | 同名变量 |

若新模型特征或顺序不同：改 `config.json` 的 `features` / `variables`，并在 `services/weather.py` 的 `FEATURE_VARIABLES` 里补上新特征的来源与换算（`FEATURE_TRANSFORMS`）。

### 3.3 更新中国边界 geojson

替换 `models/Chinageo/china_province.geojson` 即可，要求是 `FeatureCollection`，几何为面（MultiPolygon / Polygon），坐标系 WGS84 经纬度。程序会自动 `make_valid` 修复自相交。文件较大时首次加载会慢一点（当前约 0.1 秒）。

### 3.4 更新气候 / 土壤 shp

直接替换 `models/atoshp/shp/`、`models/soilshp/shp/` 下的同名 `.shp`（务必连同 `.dbf`、`.prj` 一起替换）：

- 气候图层属性字段名默认 `climate`，在 `services/geo.py::ClimateZones.value_field` 改；
- 土壤图层属性字段名默认 `SOIL_ID`，在 `services/geo.py::SoilZones.value_field` 改；
- 图层坐标系不限（WGS84 坐标会被自动投影到图层坐标系）；**`.prj` 缺失会直接报 `DATA_UNAVAILABLE`**，因为无法判断坐标含义。

参考实现：`models/soilshp/shp/soil.py`、`models/atoshp/shp/climate.py`（示例里是工作区外绝对路径，正式代码已改为 `settings.BASE_DIR` 相对路径）。

### 3.5 土壤编码表

`Soil.shp` 的 `SOIL_ID` 前两位是土类编号（1–9 类在数据里省略了百位 0，例如 `11 → 01`、`371 → 37`、`900 → 90`）。名称表在 `RE_predict_webapp/services/soil_codes.py::SOIL_CLASS_NAMES`，新增土类时在这里补一行。

## 4. 逻辑调整

### 4.1 匹配策略与置信度

都在 `RE_predict_webapp/services/matching.py`：

- `MATCH_TIERS`：匹配级别元组，可增删、换序。每级字段：
  - `code` / `label`：接口与页面展示用；
  - `confidence`：`high` / `medium` / `low`；
  - `note`：置信度说明文字；
  - `same_soil` / `same_climate` / `match_any`：该级要求的条件。
- `CONFIDENCE_LABELS`：置信度代码 → 中文（高 / 中 / 低）。

例如只想保留"土壤+气候 → 气候 → 最近"三级：从 `MATCH_TIERS` 中删掉 `soil` 那一项，`order` 会自动重排，接口语义不变。

### 4.2 气象数据源

在 `mysite/settings.py`（或用环境变量）调整：

- `WEATHER_ENDPOINT`：默认 `https://api.open-meteo.com/v1/forecast`；
- `WEATHER_MODEL`：默认空（Open-Meteo 的 `best_match`）；填 `gfs_seamless` 等模型名时会只用该模型；
- `WEATHER_TIMEOUT_SECONDS`：默认 20 秒；
- `WEATHER_FORECAST_DAYS`：默认 1 天，取当日 24 小时均值。

注意：**GFS（`gfs_seamless`）不提供土壤湿度**，设置后 `soil_moisture_*` 会是 NaN，接口返回 `WEATHER_UNAVAILABLE`（提示"气象数据缺失"）。需要换源时优先选提供土壤水分的模型。

集合预报（ensemble）接口也能用：`services/weather.py::_daily_means` 会按"参数优先、成员次之"的排布自动识别成员数并做成员平均，不依赖具体成员个数。

### 4.3 其他开关

| 位置 | 作用 |
|------|------|
| `services/predictor.py::get_predictor` | 进程内单例；改了数据要重启，或调用 `reset_predictor()` |
| `services/rf.py` | 模型 LRU 缓存，大小由 `settings.RF_MODEL_CACHE_SIZE` 控制（默认 4） |
| `services/predictor.py::_validate` | 经纬度范围校验与提示文案 |

## 5. 部署到网站

项目是标准 WSGI 应用，任何支持 Python 的托管平台都能跑。

### 5.1 通用步骤（Linux / gunicorn）

```bash
pip install -r requirements.txt
export DJANGO_DEBUG=false
export DJANGO_SECRET_KEY='请替换成随机长字符串'
export DJANGO_ALLOWED_HOSTS='your-domain.com'
python manage.py collectstatic --noinput
gunicorn mysite.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 120
```

- `collectstatic` 把静态文件收进 `staticfiles/`，由 WhiteNoise 直接提供（`requirements.txt` 已包含）；
- `--timeout` 建议 ≥ 60 秒：首次请求要加载地理数据与模型，气象请求通常 2–4 秒；
- 不装 WhiteNoise 也能跑：`mysite/urls.py` 在 `DEBUG=False` 且未检测到 WhiteNoise 时会用 Django 兜底提供 `/static/`（性能略低，适合小流量）。

### 5.2 Windows / waitress

```powershell
pip install waitress
$env:DJANGO_DEBUG="false"
$env:DJANGO_ALLOWED_HOSTS="127.0.0.1,localhost"
python manage.py collectstatic --noinput
waitress-serve --listen=0.0.0.0:8000 mysite.wsgi:application
```

### 5.3 PythonAnywhere

1. 上传代码（含 `models/` 数据目录）到 `/home/<用户名>/RE_predict_webapp`；
2. 建 virtualenv 并 `pip install -r requirements.txt`；
3. 在该项目的 Bash 控制台执行 `python manage.py collectstatic --noinput`；
4. Web 页面 → Manual configuration：
   - WSGI 文件：

     ```python
     import os, sys
     path = '/home/<用户名>/RE_predict_webapp'
     if path not in sys.path:
         sys.path.insert(0, path)
     os.environ['DJANGO_SETTINGS_MODULE'] = 'mysite.settings'
     os.environ['DJANGO_DEBUG'] = 'false'
     os.environ['DJANGO_SECRET_KEY'] = '请替换'
     os.environ['DJANGO_ALLOWED_HOSTS'] = '<用户名>.pythonanywhere.com'
     from django.core.wsgi import get_wsgi_application
     application = get_wsgi_application()
     ```

   - Static files：URL `/static/` → 目录 `/home/<用户名>/RE_predict_webapp/staticfiles`。
5. 免费账号内存较小，建议 `RF_MODEL_CACHE_SIZE=2`。

### 5.4 Render / Railway / Zeabur 等

- Build Command：`pip install -r requirements.txt && python manage.py collectstatic --noinput`
- Start Command：`gunicorn mysite.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --timeout 120`
- 根目录已提供 `Procfile`（`web: gunicorn …`），Heroku / Railway 等可直接识别；平台要求填命令时用上面一行。
- 环境变量按 5.6 设置；内存建议 ≥ 512 MB；Python 版本选 3.13（低于 3.12 装不上 Django 6.1）。

### 5.5 Docker

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN python manage.py collectstatic --noinput
ENV DJANGO_DEBUG=false
CMD ["gunicorn", "mysite.wsgi:application", "--bind", "0.0.0.0:8000", "--workers", "2", "--timeout", "120"]
```

geopandas / pyogrio / pyproj / shapely 的官方 wheel 已自带 GDAL、PROJ、GEOS，一般无需额外系统库；若安装报 GDAL 相关错误，改用预装地理组件的镜像（如 `ghcr.io/osgeo/gdal:ubuntu-small`）再 `pip install`。

### 5.6 环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `DJANGO_DEBUG` | `true` | 线上必须为 `false` |
| `DJANGO_SECRET_KEY` | 内置开发密钥 | 线上必须替换 |
| `DJANGO_ALLOWED_HOSTS` | 开发：本机；线上：`*` | 线上建议写实际域名，逗号分隔 |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | 空 | 用 `https://` 域名访问后台时填写 |
| `MODEL_DATA_DIR` | `<BASE_DIR>/models` | 数据目录换位置时用 |
| `RF_MODEL_CACHE_SIZE` | `4` | 同时缓存的模型数（每个约 20MB） |
| `WEATHER_ENDPOINT` / `WEATHER_MODEL` | forecast / 空 | 气象源 |
| `WEATHER_TIMEOUT_SECONDS` | `20` | 气象请求超时 |
| `WEATHER_FORECAST_DAYS` | `1` | 取几天预报做平均 |

### 5.7 数据库

预测功能不读写数据库；只有 `/admin/` 后台或会话功能需要。用后台时先执行 `python manage.py migrate` 并 `createsuperuser`，否则可以跳过。`db.sqlite3` 已在 `.gitignore` 中。

### 5.8 上线前安全自查

```bash
DJANGO_DEBUG=false DJANGO_SECRET_KEY=... python manage.py check --deploy
```

会剩下两条提示，按平台情况处理即可：

- `security.W008`（未开启 `SECURE_SSL_REDIRECT`）：托管平台一般已在反向代理层把 http 跳转到 https，保持默认即可；
- `security.W004`（未开启 HSTS）：确认整站只用 https 后，可在 `settings.py` 里自行加 `SECURE_HSTS_SECONDS`，加错很难撤销，按需决定。

已默认开启：`DEBUG=False` 时 `SESSION_COOKIE_SECURE` / `CSRF_COOKIE_SECURE` / `SECURE_CONTENT_TYPE_NOSNIFF` / `SECURE_REFERRER_POLICY`。生产务必设置 `DJANGO_SECRET_KEY`。

## 7. 常见故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 页面能打开但无样式、无交互 | 静态文件没收集 / 没装 WhiteNoise | `python manage.py collectstatic --noinput`；确认 `requirements.txt` 里的 whitenoise 已安装 |
| 线上访问返回 400 Bad Request | `ALLOWED_HOSTS` 不含当前域名 | 设置 `DJANGO_ALLOWED_HOSTS` |
| 中国境内坐标却提示"不在中国陆地范围内" | geojson 缺失或 `MODEL_DATA_DIR` 指错 | 检查 `models/Chinageo/china_province.geojson` 与 `settings.MODEL_DATA_DIR` |
| 提示"地理或站点数据加载失败" | shp 缺 `.prj`/`.dbf`、字段名不符、`config.json` 格式错 | 看服务端日志里的 `detail`，对照第 3.4、3.5 节 |
| 提示"气象数据缺失（可能该气象源不提供土壤湿度）" | 用了 GFS 等不提供土壤水分的模型 | 把 `WEATHER_MODEL` 置空，或换 `WEATHER_ENDPOINT` |
| 提示"未能获取 Open-Meteo 气象数据" | 服务器出网受限、接口超时 | 检查网络与代理；调大 `WEATHER_TIMEOUT_SECONDS` |
| 提示"该站点的随机森林模型不可用" | `rf_models/<站点>_rf.joblib` 缺失或损坏 | 补齐模型文件；看日志确认站点编码 |
| 首次预测特别慢（数秒） | 首次加载 geojson/shp/模型 | 正常现象；可预热一次请求 |
| 内存占用高 / 被平台 OOM | 模型缓存过大、worker 太多 | 调小 `RF_MODEL_CACHE_SIZE`；`--workers 1~2` |
| 502 / 504 网关超时 | worker 超时时间小于首次预测耗时 | gunicorn `--timeout 120`，平台侧超时同步调大 |
| 测试报 `GEOS`/`PROJ` 相关导入错误 | 依赖未装全 | `pip install -r requirements.txt` |

日志：业务日志在 `RE_predict_webapp` logger（settings 里 `LOGGING`），预测完成、气象失败、未预期异常都会记录。

## 8. 性能与容量

- 进程启动：地理数据懒加载，`manage.py` 的运维命令不会被拖慢；
- 首次预测：加载 geojson+shp 约 0.3 秒、命中站点模型约 0.1–1.2 秒、气象接口 2–4 秒；
- 后续预测：只有气象接口耗时（约 2 秒）；
- 内存：Python+geopandas 约 150 MB，每个缓存模型约 20 MB（默认 4 个）；
- 并发：Open-Meteo 是外部瓶颈，高并发建议加缓存（例如对同一坐标做 10 分钟结果缓存）或限制频率。

## 10. 修改约定

1. 业务逻辑放 `services/`，视图只负责参数与响应；不要在视图里重复实现匹配/取数逻辑。
2. 新增外部依赖后同步更新 `requirements.txt`。
3. 改匹配策略、数据路径、分区字段名时，连同 `tests.py` 一起更新并跑 `python manage.py test RE_predict_webapp`。
4. 注释只写"为什么"和不直观的约定，不复述代码。
5. 所有路径从 `settings.BASE_DIR` 推导，不写死盘符或工作区外绝对路径。
6. 验收前自查：`manage.py check` → 测试全绿 → 浏览器/curl 跑一次境内、境外各一个坐标。
