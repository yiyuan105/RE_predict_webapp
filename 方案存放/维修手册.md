
## 2. 本地运行与自检

```bash
# 安装依赖
pip install -r requirements.txt

# 启动（manage.py 里加了自动打开浏览器，默认 http://127.0.0.1:8000/）
python manage.py runserver

# 系统检查
python manage.py check

# 测试（67 个）
python manage.py test RE_predict_webapp
```

```bash

```

## 3. 数据更新

### 3.1 增删或修改站点

编辑 `RE_predict_webapp/config.json` 的 `stations`：

```json
"NEW": {
  "site_name": "新站点名称",
  "ecosystem": "Forest",
  "veg_type": "...",
  "lat": 30.0,
  "lon": 110.0,
  "soil_type": "红壤",
  "climate_type": "北亚热带湿润地区"
}
```

- 站点分区类型优先由 shp 自动查询；`soil_type` / `climate_type` 只在 shp 未覆盖该点时兜底，写错了不会报错但会参与匹配，建议照 shp 结果填写。
- 新增站点必须同时放入模型 `models/rf_models/NEW_rf.joblib`，否则命中时会返回 `MODEL_UNAVAILABLE`。
- 对外页面不再展示站点经纬度与模型文件；新增站点若要出现在「站点」页，还要在 `training` 段补一条训练结果（见 6.1）。
- 不需要改任何代码；重启服务生效（单例缓存在进程内）。

### 3.2 替换随机森林模型

把同名的 `<站点>_rf.joblib` 覆盖到 `models/rf_models/`，重启服务。模型输入是 `config.json` 里 `features` 顺序的 6 个特征：

| 特征 | 含义 | 来源 |
|------|------|------|
| `rn` | 净辐射 = 短波辐射 × 0.6 | `shortwave_radiation` |
| `ts1` | 气温 | `temperature_2m` |
| `rh` | 相对湿度 | `relative_humidity_2m` |
| `pa` | 气压 | `surface_pressure` |
| `soil_moisture_0_to_7cm` | 0–7cm 土壤水分 | 同名变量 |
| `soil_moisture_7_to_28cm` | 7–28cm 土壤水分 | 同名变量 |

若新模型特征或顺序不同：改 `config.json` 的 `features` / `variables`，并在 `services/features.py` 的 `FEATURES` 里补上新特征（`variable` 与可选 `transform`）。`weather.py` 的取数映射由它派生，不用改两处。

> 以上特征只用于内部建模与取数，**不会出现在页面或对外接口里**（预测接口的 `weather.features` 属 v1.1.0 遗留契约，页面不展示）。

### 3.3 更新中国边界 geojson

替换 `models/Chinageo/china_province.geojson` 即可，要求是 `FeatureCollection`，几何为面（MultiPolygon / Polygon），坐标系 WGS84 经纬度。程序会自动 `make_valid` 修复自相交。文件较大时首次加载会慢一点（当前约 0.1 秒）。

### 3.4 更新气候 / 土壤 shp

直接替换 `models/atoshp/shp/`、`models/soilshp/shp/` 下的同名 `.shp`（务必连同 `.dbf`、`.prj` 一起替换）：

- 气候图层属性字段名默认 `climate`，在 `services/geo.py::ClimateZones.value_field` 改；
- 土壤图层属性字段名默认 `SOIL_ID`，在 `services/geo.py::SoilZones.value_field` 改；
- 图层坐标系不限（WGS84 坐标会被自动投影到图层坐标系）；**`.prj` 缺失会直接报 `DATA_UNAVAILABLE`**，因为无法判断坐标含义。

参考实现：`models/soilshp/shp/soil.py`、`models/atoshp/shp/climate.py`（示例里是工作区外绝对路径，正式代码已改为 `settings.BASE_DIR` 相对路径）。

### 3.5 土壤编码表

`Soil.shp` 的 `SOIL_ID` 前两位是土类编号（1–9 类在数据里省略了百位 0，例如 `11 → 01`、`371 → 37`、`900 → 90`）。名称表在 `RE_predict_webapp/services/soil_codes.py::SOIL_CLASS_NAMES`，新增土类时在这里补一行。

## 4. 逻辑调整

### 4.1 匹配策略与置信度

都在 `RE_predict_webapp/services/matching.py`：

- `MATCH_TIERS`：匹配级别元组，可增删、换序。每级字段：
  - `code` / `label`：接口与页面展示用；
  - `confidence`：`high` / `medium` / `low`；
  - `note`：置信度说明文字（会展示给访客，注意对外口径）；
  - `same_soil` / `same_climate` / `match_any`：该级要求的条件。
- `CONFIDENCE_LABELS`：置信度代码 → 中文（高 / 中 / 低）。

例如只想保留"土壤+气候 → 气候 → 最近"三级：从 `MATCH_TIERS` 中删掉 `soil` 那一项，`order` 会自动重排，接口语义不变。

### 4.2 气象数据源

在 `mysite/settings.py`（或用环境变量，见《云端部署与更新》）调整：

- `WEATHER_ENDPOINT`：默认 `https://api.open-meteo.com/v1/forecast`；
- `WEATHER_MODEL`：默认空（Open-Meteo 的 `best_match`）；填 `gfs_seamless` 等模型名时会只用该模型；
- `WEATHER_TIMEOUT_SECONDS`：默认 20 秒；
- `WEATHER_FORECAST_DAYS`：默认 1 天，取当日 24 小时均值。

注意：**GFS（`gfs_seamless`）不提供土壤湿度**，设置后 `soil_moisture_*` 会是 NaN，接口返回 `WEATHER_UNAVAILABLE`（提示"气象数据缺失"）。需要换源时优先选提供土壤水分的模型。

集合预报（ensemble）接口也能用：`services/weather.py::_daily_means` 会按"参数优先、成员次之"的排布自动识别成员数并做成员平均，不依赖具体成员个数。

换气象源后记得同步改来源注明（见 6.2），否则页面上的署名仍会写着原来的服务。

### 4.3 其他开关

| 位置 | 作用 |
|------|------|
| `services/predictor.py::get_predictor` | 进程内单例；改了数据要重启，或调用 `reset_predictor()` |
| `services/rf.py` | 模型 LRU 缓存，大小由 `settings.RF_MODEL_CACHE_SIZE` 控制（默认 4） |
| `services/predictor.py::_validate` | 经纬度范围校验与提示文案 |
| `services/errors.py` | 各错误码的默认提示；`message` 会直接展示给访客，`detail` 只进日志 |

## 5. 对外接口字段范围

对外可见层（页面 + 接口）只允许出现下表中的字段。**新增接口或给现有接口加字段前，先确认它属于对外可见信息**——路径、文件名、模型文件、输入特征、内部变量、模块名一律不进对外字段。

| 地址 | 方法 | 对外返回 |
|------|------|----------|
| `/` | GET | 首页（三栏布局：左三框 / 主内容 / 公告边栏） |
| `/?lat=…&lon=…` | GET | 旧版纯文本预测结果（保留兼容，成功输出与 v1.1.0 一致） |
| `/stations/` | GET | 模型训练情况页 |
| `/sources/` | GET | 数据来源注明页 |
| `/api/predict/` | GET | `prediction` / `confidence` / `station` / `matching` / `weather` / `meta`（v1.1.0 契约未改） |
| `/api/stations/` | GET | `count` / `display` / `stations[]`（`code`、`train_size`、`test_size`、`train_mse`、`train_r2`、`test_mse`、`test_r2`、`model_type`）/ `meta` |
| `/api/sources/` | GET | `count` / `sources[]`（`key`、`name`、`category`、`purpose`、`update`）/ `meta` |
| `/api/announcements/` | GET | `count` / `announcements[]`（`title`、`body`、`published_at`）/ `meta` |

- 三个只读接口都用 `@require_GET`，写请求返回 **405**；对外不提供任何公告写入接口，发布 / 下架在服务端改配置完成。
- 统一外壳：成功 `{"ok": true, …}`；失败 `{"ok": false, "error": {"code": "…", "message": "…"}}`，`message` 是面向访客的整句中文。
- 错误码与状态码：`INVALID_INPUT`(400)、`OUT_OF_CHINA`(422)、`WEATHER_UNAVAILABLE`(503)、`MODEL_UNAVAILABLE`(503)、`DATA_UNAVAILABLE`(500)、`INTERNAL_ERROR`(500)。
- 数据缺失时返回可读提示而不是让页面崩溃；`tests.py::OutwardLeakTests` 会扫描三页 HTML 与三个只读接口的 JSON，发现路径、文件名、特征名或 `/api/` 字样就报错，改动接口后先跑测试。

## 6. 对外展示内容维护

三块对外内容各自只有一处数据源，页面、接口与结果区标注同源，改完刷新页面即可（模板与静态文件不需要重启，`config.json` / `announcements.json` 每次请求重新读取）。

### 6.1 训练情况（`config.json` 的 `training` 段）

```json
"training": {
  "model_type": "随机森林 / RandomForestRegressor",
  "display": { "mse_digits": 4, "r2_digits": 4 },
  "records": {
    "NMG": {"train_size": 2045, "test_size": 512,
            "train_mse": 1.1417, "train_r2": 0.9947,
            "test_mse": 17.8560, "test_r2": 0.9263}
  }
}
```

- 键是站点编码，必须与 `stations` 段一致；站点清单里没有的编码会跳过并记一条 warning。
- 八个对外字段之外的任何信息都不会展示：**整条记录只会输出编码、样本数、四项指标与模型类别**。
- `display` 是页面展示精度（小数位数），由接口下发给前端格式化；改成 `{"mse_digits": 4, "r2_digits": 3}` 即可按 R² 三位小数显示，前端不用动。默认 4/4，与训练结果表给出的位数一致，页面数值可直接对照。
- 校验规则：样本数必须是非负整数，`mse` / `r2` 必须是有限的非负数；缺字段或类型不对会返回 `DATA_UNAVAILABLE`，提示里带站点编码，前端显示为可读错误。
- 新增站点：先在 `stations` 段加站点、放模型，再在 `records` 里加一条；两条记录的键要一致，测试会校验覆盖情况。
- 站点缺少训练记录时页面只是少一行，并会在服务端日志里留下「以下站点缺少训练情况：…」。

### 6.2 来源注明（`services/sources.py` 的 `ATTRIBUTIONS`）

- 每项只有五个字段：`key`（接口标识）、`name`（来源名称，同时用作预测结果区的署名）、`category`（来源类型）、`purpose`（用途）、`update`（更新方式）。
- 新增来源：往 `ATTRIBUTIONS` 里加一项，顺序即来源页展示顺序；不需要改模板或接口。
- 下线来源：删掉对应条目；结果区标注会同步消失（标注只显示命中的那几项）。
- 文案要求：只用自然语言说明"是什么、用来做什么、怎么更新"，**不要写路径、文件名、接口地址、变量名**。测试会检查这五项字段里不含 `/`、`\`、`.shp`、`http`、`SOIL_ID` 等字样。
- 换气象数据服务时，除了改环境变量，还要改这里 `weather` 的 `name`，否则署名胜名与实际来源不符。

### 6.3 公告（`RE_predict_webapp/announcements.json`）

```json
{
  "announcements": [
    {
      "title": "标题由发布方拟定",
      "body": "正文由发布方拟定，可以写多行。",
      "published_at": "2026-11-20",
      "active": true
    }
  ]
}
```

发布 / 维护流程（服务端操作，不经过网页）：

1. 编辑 `announcements.json`（线上的话改挂载进容器的那个文件，见《云端部署与更新》）；
2. 新增公告：在 `announcements` 数组里加一条，填 `title`、`body`、`published_at`；
3. 修改公告：直接改对应条目的字段；
4. 下架公告：把 `active` 设为 `false`（保留内容便于日后恢复）或删除该条；
5. 保存后接口立即生效（每次请求重新读取文件），无需重启；
6. 用 `curl http://127.0.0.1:8000/api/announcements/` 或刷新首页右侧边栏确认。

规则与排错：

- 排序：按 `published_at` **倒序**（最新在上），时间相同按文件顺序。
- `published_at` 接受 `2026-11-20` 或带时区的 ISO 时间（`2026-11-20T09:00:00+08:00`）；不带时区的按 UTC 比较。
- 单条缺标题、缺正文或时间无法识别时，该条会被跳过并在日志里记一条 warning，其余公告照常展示。
- 整份 JSON 语法错误或结构不对：接口返回 500 `DATA_UNAVAILABLE`，首页边栏显示可读提示，页面不会白屏。
- 文件不存在按"暂无公告"处理（页面显示「暂无公告。」）。
- 正文只写面向访客的自然语言：不要出现文件地址、内部实现或与技术实现相关的细节。

### 6.4 页面文案与网页简述

| 想改的内容 | 位置 |
|------------|------|
| 页面标题、网页简述、顶部导航文案、首页左侧三框文案 | `RE_predict_webapp/content.py` 的 `PAGES` |
| 页面里的静态文字（字段名、按钮、表头、页脚） | 对应模板中 `{# 文案：… #}` 注释下的标签 |
| 动态提示（加载中、失败、复制、筛选统计、空结果） | 各页脚本顶部的 `TEXT` 常量：`app.js` / `training.js` / `sources.js` / `notices.js` / `common.js` |

> **模板注释必须写成 `{# … #}`**，不要用 `<!-- … -->`：HTML 注释会原样输出到页面源码里，一旦写了文件名就等于对外暴露了内部信息。`tests.py::OutwardLeakTests::test_pages_do_not_render_template_comments` 会兜底检查。

## 7. 日志与常见故障排查

日志在 `RE_predict_webapp` logger（`settings.LOGGING`），预测完成、气象失败、未预期异常、公告坏条目都会记录；容器里用 `docker compose logs` 查看（见《云端部署与更新》）。

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 中国境内坐标却提示"不在中国陆地范围内" | geojson 缺失或 `MODEL_DATA_DIR` 指错 | 检查 `models/Chinageo/china_province.geojson` 与 `settings.MODEL_DATA_DIR` |
| 提示"地理或站点数据暂时无法加载" | shp 缺 `.prj`/`.dbf`、字段名不符、`config.json` 格式错 | 看服务端日志里的 `detail`，对照第 3.4、3.5 节 |
| 提示"气象数据缺失（可能该气象源不提供土壤湿度）" | 用了 GFS 等不提供土壤水分的模型 | 把 `WEATHER_MODEL` 置空，或换 `WEATHER_ENDPOINT` |
| 提示"未能获取 Open-Meteo 气象数据" | 服务器出网受限、接口超时 | 检查网络与代理；调大 `WEATHER_TIMEOUT_SECONDS` |
| 提示"该站点的模型暂不可用" | `rf_models/<站点>_rf.joblib` 缺失或损坏 | 补齐模型文件；服务端日志里有具体站点与路径 |
| 站点页少了一行 / 数值与预期不符 | `training.records` 缺条目或算错 | 对照 6.1 校验规则改 `config.json`；看是否只有该站点缺记录 |
| 来源页缺项 / 署名与气象源不符 | `ATTRIBUTIONS` 未同步 | 按 6.2 增删条目或改 `name` |
| 首页公告显示「暂无公告。」 | `announcements.json` 为空、条目都被下架、挂载路径不对 | `curl /api/announcements/` 看返回；核对文件路径与 JSON 结构 |
| 公告接口 500 `DATA_UNAVAILABLE` | JSON 语法错或顶层不是 `{"announcements": [...]}` | 用 JSON 校验工具修好文件 |
| 改了公告/训练数据页面没变 | 浏览器缓存，或改的是镜像内文件而请求读的是挂载文件 | `Ctrl+F5`；确认挂载路径与 `DataPaths` 一致 |
| 首次预测特别慢（数秒） | 首次加载 geojson/shp/模型 | 正常现象；可预热一次请求 |
| 内存占用高 / 被 OOM Kill | 模型缓存过大、worker 太多 | 调小 `RF_MODEL_CACHE_SIZE`（部署侧参数见《云端部署与更新》） |
| 测试报 `GEOS`/`PROJ` 相关导入错误 | 依赖未装全 | `pip install -r requirements.txt` |
| 测试里 `OutwardLeakTests` 失败 | 页面或只读接口混进了路径/文件名/特征名 | 按报错里的 token 定位模板、文案或接口字段 |

## 8. 性能与容量

- 进程启动：地理数据懒加载，`manage.py` 的运维命令不会被拖慢；
- 首次预测：加载 geojson+shp 约 0.3 秒、命中站点模型约 0.1–1.2 秒、气象接口 2–4 秒；
- 后续预测：只有气象接口耗时（约 2 秒）；
- 内存：Python+geopandas 约 150 MB，每个缓存模型约 20 MB（默认 4 个）；
- 并发：Open-Meteo 是外部瓶颈，高并发建议加缓存（例如对同一坐标做 10 分钟结果缓存）或限制频率；
- 训练情况接口每次请求读一次 `config.json`（几 KB），公告接口每次请求读一次 `announcements.json`，没有额外缓存层，便于改完即生效。

## 10. 修改约定

1. 业务逻辑放 `services/`，视图只负责参数与响应；不要在视图里重复实现匹配/取数逻辑。
2. 对外内容（训练情况、来源注明、公告、页面文案）只维护一处数据源，页面与接口都从服务层取，不要在前端另写一份。
3. 对外可见层不得出现路径、文件名、模型文件、输入特征、内部变量与模块名；新增接口字段前先对照第 5 节。
4. 模板注释一律用 `{# … #}`；错误文案写成面向访客的整句话，排查信息放 `err.detail`。
5. 新增外部依赖后同步更新 `requirements.txt`；部署相关改动同步写进《云端部署与更新》。
6. 改匹配策略、数据路径、分区字段名或对外字段时，连同 `tests.py` 一起更新并跑 `python manage.py test RE_predict_webapp`。
7. 注释只写"为什么"和不直观的约定，不复述代码。
8. 所有路径从 `settings.BASE_DIR` 推导，不写死盘符或工作区外绝对路径。
9. 验收前自查：`manage.py check` → 测试全绿 → 浏览器/curl 跑一次境内、境外各一个坐标，并确认三页页面里搜不到 `.joblib`、`.shp`、`models/`、`/api/` 等字样。
